# 大数据挑战赛 Skill：赛场通用执行与最终验收（v2.9）

本手册针对**今年题目未知、最终以论文为核心交付物**的大数据比赛；不固定年份、模型、赛道或子问题数量。每道题以**正确回答、有效求解、可靠结论和论文逻辑**为优先级。不是模型越多越好，也不是指标只要好看就算回答了题意。

## 实战采用两级验收，别让检查器反过来决定科学问题

**级别 A — 通用论文研究包**：官方子问题均有答复；方法选择有假设依据；科学 Reviewer 实际做过独立复核；可靠性、扰动与局限可追溯；摘要、核心章节、结论能回指证据；提交方式来自当届官方要求。任何算法族都能进入本级，包括文本分析、理论论证、规则系统、可解释性、非传统数值模型与混合研究。使用 `competition_readiness.py` 检查**文件/声明的完整性**。绿色输出仍不等于科学审核通过。

**级别 B — 适用时的数值证据链**：当且仅当任务确实属于现有参考求解器支持的数学类型，而且有合法原子数值数据时，使用 `project_evidence_chain.py` 核查指标三方回读、独立计算、不变式和稳定性锚点。不适用的任务不能虚构“精确最优”、“sign-flip 显著”或“已复算成功”来满足级别 B；另行做项目专属独立复核并保留证据，最终仍在级别 A 留下人工验证记录。

## 赛题公布后立即执行

1. **重构题意而不是套模型**：抽取官方每问的研究对象、目标、单位、约束、实际交付文件、评分和可以在预测时合法获取的特征；不能凭历届 A/B 题型推断今年题型。
2. **按数据和目标选研究路线**：做数据字典、数据完整性/泄漏审计，明确任务是描述、统计推断、分类、回归、时序、图、视觉、优化、仿真、文本还是混合；至少考虑一个合理的简单 baseline 或解析检查。
3. **小题/已知答案先行**：在真正耗费算力之前检查数学式、单位和输出是否符合题目；对优化先检查可行、对预测先检查切分，对统计检验先审查识别和假设。
4. **正式实验有来源**：记录版本、数据拆分、随机数、计算资源、异常值、失败案例和实际结果。禁止把合成单元测试当真题跑分。不要在官方测试集上调模型。
5. **独立审查和稳健性**：用另一种公式、手算例、不同求解器或审稿人攻击关键结论，核查不确定性、参数扰动、反事实或失败样例。稳定地算错仍然是错。
6. **只把验证过的结论写进论文**：围绕“目标→障碍→为什么这个方法→关键求解→验证证据→不确定性→回答原题”组织正文。优秀论文作为写作范例而非标准模型；不能把未阅读 PDF 的章节结构称为已总结的规律。
7. **最后打包**：核对本届官方文件名、格式、匿名、引用、代码/结果文件和提交时间。正式题目没有要求的额外文件不必照搬往届，Kaggle 提交格式不是本 Skill 的默认规范。

## 论文两次审稿不可互相替代

- **Scientific reviewer**：先从题目重新推导模型是否回答所问，独立复核至少一个核心数值或理论主张；明确失败案例、数据泄漏、优化约束/最优性和统计假设。遇到不支持的强结论，降格或重做，而不是通过论文修辞补救。
- **Editorial reviewer**：检查摘要是否完整回答任务，章节安排是否遵循当前研究问题，过渡是否解释方法选择，图表是否真正支撑结论，结论是否超出数据范围。审核是论证链而非“润色得像获奖论文”。

## 使用通用资料完备性检查

创建符合 [研究包字段说明](../templates/competition-readiness-record.md) 的 `review-package.json`，并根据真实文件内容填写每个 `files[].sha256`（可使用 Python 的 hashlib 或系统 `sha256sum`），然后运行：

```bash
python skills/big-data-competition-skill/tools/competition_readiness.py --record review-package.json --artifact-root path/to/outputs
```

检查官方子问题数、论证条目、结果/图表引用的证据文件、论文的各逻辑功能、科学检查说明与官方交付项。**不验证自称的 Reviewer 身份、不从网络读取官方要求、不认证科学真理**；输出 `documentation_consistent_pending_expert_review` 的意思是*记录可审阅*，而不是通过学术评审。

## 如何决定“Skill 工程版可以结束迭代”

工程收尾需要满足：通用工作流可适应未知题型；专用计算工具能说明适用/不适用；真正错误的结果/缺失的论文证据能被正反例阻断；活动 SKILL、manifest、索引和插件版本一致；PR 与主分支 CI 通过。**真实当届模型的正确性、16 篇获奖论文的逐篇写作结构提炼**是另外的实证工作，不能凭软件 CI 冒充完成。

遵守 [原有通用求解正确性协议](solution-validity.md)、[项目级数值完整性检查](project-evidence-chain.md) 与 [论文论证结构](paper-argumentation.md)。
