# Stability, Reliability and Uncertainty — 按任务自适应

## 先区分四个对象

- 正确性：模型公式、实现及输出是否真的回答了题目。
- 可靠性：评估方案能否代表实际应用，样本误差与评价不确定性有多大。
- 稳定性：同一问题在合理扰动下，结论/决策改变多少。
- 可复现性：相同版本、数据、环境与随机数设置是否能得到相符结果。

**重复运行不保证方法正确；高平均分不保证低波动；波动小也可能稳定地算错。**

## 扰动如何选择

| 任务特性 | 应考虑的扰动与检查 | 注意 |
|---|---|---|
| 分类/回归 | 随机初始化、合规 fold/分组、数据缺失、测量误差、阈值、少数类/子群 | 不可在正式 test 上挑参；CI 只跑合成检查不能当真实性能 |
| 时序/时空 | 滚动时间窗、事件分组、漂移/极端时期、空间留区 | 随机拆分通常破坏验证协议 |
| 优化/调度 | 需求扰动、容量、成本、约束边界、求解器容差、多起点 | 每次都复查可行性；最优值/最优界与启发式上界区分 |
| 仿真/随机过程 | 独立随机流、重复次数、步长、终止条件、置信区间的适用假设 | 同一随机种子重新跑只证实可复现，不能表征随机波动 |
| 统计推断/因果 | 识别假设、混杂、异常点、区间/模型假设、安慰剂或负控 | 相关不是因果，统计显著不代表实际意义 |
| 确定性数值算法 | 网格/步长、浮点精度、收敛阈值、解析极限、小规模精确解 | 同一输入重复得到相同值不证明数值误差小 |

正式论文必须明确**扰动维度、覆盖范围、接受条件、是否实际执行、失败案例、结论是否改变**。不要机械要求每个问题跑 100 个随机种子，而应针对最可能推翻结论的假设选取高信息量检查。

## 实际多次运行汇总脚本

只输入真实测量。各 `run_id` 唯一；`protocol_id`/`data_version` 和评价指标口径固定。`max_range` 与可选 `min_paired_gain` 必须在查看结果之前声明。若任务不是“换随机种子”，`perturbation` 写真实扰动维度，例如窗口或成本，不要虚报独立性。

```bash
python skills/big-data-competition-skill/tools/stability_audit.py --record path/to/actual_repetitions.json
```

[填写示例与字段说明](../templates/stability_record.md)；脚本计算观测范围、均值、样本 SD 和可选同协议配对基线差。阈值不满足输出 `unstable`；若 superiority claim 未通过预设的成对门槛输出 `unsupported_improvement_claim`；记录不完整为 `blocked`。仅当所测扰动的观测范围低于门槛才返回 `stable_under_tested_perturbations`，这**不能解释为普遍稳定**。

- 少量重复不能支持总体分布或可靠置信区间。
- 区间/显著性需选择符合独立性与采样设计的有效统计方法，不能用观测 min–max 冒充。
- 数据泄漏、公式错误、约束失败时，即使 `stable_under_tested_perturbations` 也必须阻断论文的正确性结论。


## v2.7 统计与仿真的独立验算边界

[扩展复算协议](extended-oracles.md) 新增配对符号翻转精确 p 值、iid 伯努利 Wilson 区间及时间折内误差指标核对。这些属于**在指定数学条件下的数值审核**；零假设交换性、抽样独立、多重检验校正、未来数据可用性和检验阈值的真正事先登记需额外认证。不能把模拟精度达标等同真实仿真过程可靠。
