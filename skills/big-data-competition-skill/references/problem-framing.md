# Problem Framing

建立 Competition Contract 与子任务表。

每个子任务至少记录：
- objective
- structure
- input
- output
- metric
- information_cutoff
- constraints
- dependencies
- unknowns
- validation_plan

禁止根据代码、文件名或已有答案反推题意。题面不明确时保留 ambiguity，不能用默认经验补齐。

## Research-question conversion

把题面要求转化为可验证问题：

- 要解释什么？
- 要预测什么？
- 要比较什么？
- 要优化什么？
- 要模拟什么？
- 要估计什么不确定性？

每个问题都要能连接到数据、方法、指标和最终论文 claim。
