# Universal Solution Validity & Reliability Protocol

目标：先证明解答确实解决了**当届赛题要求的问题**，再写出有说服力的论文。不预设问题数量、模型、数据类型或指标，不照搬任何往届赛题。

## 三种互不替代的正确性

1. **题意正确**：每问的目标、输出、单位、约束及允许使用的信息均与官方要求一致；漂亮的代理指标不能替代原题的回答。
2. **模型与计算正确**：变量、假设、公式、量纲、边界条件、特征生成、实现算法及求解器状态自洽；对极端或可手算小规模样例进行独立复算。
3. **结论正确**：论文数字可回指已验收结果；结论不超出验证、假设与样本范围。相关不等于因果；最好的一次结果不等于全局最优；单次复现不等于稳定。

可靠性关注评估设计、误差和不确定性；稳定性关注参数、数据、种子和边界扰动造成的结果变化。两者分别审核，均不能靠 GitHub CI 的绿色标记代替。

## 每个真实子问题的 Q0–Q5 验收流程

**Q0 题目契约：**冻结官方目标、输出、单位、数据时点、约束、评价规则和未知事项。没有官方指标时，事先选出能够衡量该目标的指标，说明局限。

**Q1 建模逻辑：**核对变量定义、适用边界、假设、约束、量纲；主动找反例。建立简单基准、理论界或手工可算小例子，按任务择其一，不强迫证明类任务跑机器学习。

**Q2 算法求解：**检查实现不变式、关键数学步骤、求解器状态、最优性声称与实际保证；使用不同公式、简化问题或另一求解器复核部分结果。程序没有报错不代表算法正确。

**Q3 方法与可靠性：**预测要做无泄漏且匹配时点/实体的评估；统计推断要解释估计量与不确定性；因果需识别策略与混杂审查；优化需可行性与最优间隙/启发式边界；仿真需重复实验与收敛；描述性分析需明确分母与统计口径。混合问题逐任务组合相关闸门。

**Q4 扰动与反例：**按科学目的改变时间窗、分组、超参数、随机种子、数据缺失、约束或极端输入。事先确定判定标准；保留失败样本和不稳定结果。不能将少数种子的波动分析叫作严格概率保证。

**Q5 结论审核：**每条主张绑定具体数据、运行产物、独立检查、适用范围和反例；不能把“可能”偷换为“证明”，不能以一份样本推广全部情境。

## 独立 Reviewer 必须做什么

- 不照抄原模型作者的叙述，重新对照题意判断输出是否匹配。
- 尝试一个边界值、反例或小规模手算。
- 使用独立求解、交叉实现或人工复算验证至少一个关键结果。
- 主动攻击验证方案：未来信息、实体重叠、训练污染、指标口径、约束漏写。
- 检查最差子群、失败案例和最容易过度推断的句子。
- 若关键模型公式、独立复核、约束或结论缺乏证据，阻断定稿而不是只润色文字。

## 可执行方案质量覆盖检查

复制 [通用方案复核记录](../templates/solution_quality_record.md)，按真实题目填写，然后运行：

```bash
python skills/big-data-competition-skill/tools/solution_quality_gate.py --record project/quality_review.json
```

审核 Q0–Q5 记录、独立复核、必要的任务专项验收和结论证据。结果 `review_ready` **仅代表记录的自报检查覆盖完整**，不等于证明结果科学正确。工具不会打开或认证那些 artifact 的真实性；必须由独立 Reviewer 实际检查。`pending`、`failed`、`unknown`、没有证据的 `passed` 或强行跳过必要检查均不能定稿。

| 状态 | 含义 | 是否可作为已验证结论 |
|---|---|---|
| pending / unknown | 未检查或证据不足 | 不可以 |
| failed | 已有反例或不满足要求 | 必须修复或限制结论 |
| passed（真实证据） | 某个条件下执行过该项检查 | 仅限被检查的范围 |
| not_applicable（理由充分） | 明确与此任务无关 | 说明原因，不推断其他项通过 |

没有加权分数可以让好看的论文抵消算错的问题。关键子问未回答、验证泄漏、约束违反或强结论不成立即为阻断项。

## 稳定性与统计边界

阅读 [稳定性分析](stability-and-uncertainty.md)，在实际运行后使用 `stability_audit.py` 汇报均值、样本标准差、观测范围和可选成对基线差异。稳定性阈值必须预先声明；这些摘要**不是置信区间或显著性检验**，未做扰动实验不得宣称稳定。

最后按 [论文论证逻辑](paper-argumentation.md) 从题意、方法依据、独立验证、证据、解释到局限组织正文，而不是堆砌算法名称。

## v2.5 从审核记录到求解结果反证

审稿人填写一份 `passed` 质量表只能说明完成某些文档步骤，不能证明实际数值结果满足题目要求。参考 [数值不变式与证伪](result-falsification.md) 先从本届正式题目预定义必要边界、守恒和约束，再对**真实求解输出**验算；必须保留失败案例。成功意味着已声明的必要条件成立，而不是模型必然正确。

## v2.6 独立复算先于强结论

在合适的题型下，除了必要条件，还应遵照 [独立参考实现与黄金反例](independent-recomputation.md)，从真实原始合法观测重新计算关键指标，或对对应的小规模整数优化子模型进行独立精确枚举。失败时优先调查算法/数学模型，不要只修改论文。模型假设或数据来源如存在共同错误，两个一致的程序仍可能同时出错。


## v2.7 非固定题型的额外科学参考验算

可以按 [四类扩展独立参考算法](extended-oracles.md) 对时序预测的滚动切分和原始误差、配对检验双侧 p 值、iid 随机仿真 Wilson 置信区间及盒约束可分凸二次优化的解析解进行复核。先检验实际问题是否符合数学和统计前提，再决定该验证能支持多强的结论。工具重算成功不能证明原始数据独立、特征未泄漏或学术主张普遍成立。
