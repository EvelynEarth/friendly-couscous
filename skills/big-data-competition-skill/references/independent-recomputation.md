# 独立复算与已知答案反证（v2.6 · 通用赛题）

## 目标：修复“程序稳定地产生错误答案”

**程序可运行、图表整齐、指标文件哈希一致、必要约束通过，都不保证模型及结论正确。** 在任何未知赛题正式发表结论前，必须另走一条**尽量不复用原求解代码**的检验路线，并尝试找能推翻解答的反例。

对应操作分为三个强度：

1. **定义/目标正确**：原题要求的输出究竟是什么，单位、允许使用的信息、约束和评价口径是什么？如果问题不是纯预测，就不要把高分类准确率视为正确回答。
2. **实现与数值正确**：与主程序不同的公式、小规模手算、另一求解器或参考算法重算。**真正的独立性要检查共同代码/共同数据/共同错误源**。训练者写两段调用同一库的代码，不等于独立验证。
3. **推断正确**：检查评价切分、标签可用时点、统计不确定性、参数扰动、最优性或因果识别范围。数值复算不等于这些条件已经满足。

### 已接入的独立数值参考实现

代码：[独立参考求解器](../tools/independent_oracle.py)；[填写模板](../templates/independent-oracle-case.md)。

命令：

```bash
python skills/big-data-competition-skill/tools/independent_oracle.py --case path/to/independent_check.json
```

| 模式 | 实际计算内容 | 能发现什么 |
|---|---|---|
| `regression` | 从逐条 `actual`/ `predicted` 重新计算 MAE、RMSE | 汇总指标被算错、被抄错、样本维度不一致 |
| `classification` | 从真实标签和预测标签独立构造混淆矩阵，按**固定标签集合**重算 accuracy、macro precision/recall/F1；零分母视作 0 | 类别指标公式与平均方式错误、遗漏缺失类别、虚报指标 |
| `bounded_integer_linear` | 用 **stdlib 的穷举枚举**，对小规模整数线性模型检查目标值、所有约束、可行点和精确最优值 | *可行但次优*、公式值算错、最优性被夸大、实际不可行 |

整数枚举模式的目标和约束系数必须是**精确整数**，决策变量的上下界必须是有限整数，枚举状态数最多 100,000；超过限制会主动阻断而不是宣称“已精确求解”。涉及连续变量、随机优化、非线性求解和大型 NP-hard 问题时，此工具**不能证明全局最优**，应设计小规模可精确求解子实例/上下界/KKT 或适合该领域的单元测试。

上述模式的 `status=recomputed_match` 或 `exact_small_case_match` 只说明**提供给它的这个数据/小实例**符合重算结果，不代表整场比赛问题被彻底验证，更不是模型泛化性能证明。

## 方法测试如何比“同一段代码跑两遍”更强

- **黄金样例（golden oracle）**：手工算得出的明确期望值，如 MAE/RMSE、macro-F1、小型优化最优目标；与程序输出强比较。
- **故意注入错误（mutation/adversarial）**：把报告的 F1 改错、将最优解改成可行次优解、越过仓储容量、使用非法 NaN/没有实际证据，测试工具必须拒绝。
- **变形关系（metamorphic）**：例如回归真实值和预测值同时平移不改变 MAE/RMSE；合法的类别重命名不改变宏平均指标；加冗余约束不改变原整数优化的最优值。
- **独立复现**：若确实取得原始比赛数据和训练结果，重新计算某几个真实中间量，比较不同求解器/公式/基准；任何冲突必须先复查，不能直接在论文中选更好的答案。

本仓库 `tests/test_bigdata_independent_oracle.py` 包含 **20 个小型人工可推导的正反例**；其通过意味着测试工具对这些**合成场景**符合预期，而不是完成了真实 MathorCup 赛题复现。

## 科学检验边界

- 该脚本不生成预测，不训练模型，也不能判断 `actual` 是否被未来信息污染；预测任务还需要独立 holdout / 时间 / 实体隔离。
- 分类的 `labels` 是评价时预先确定的完整类别集合，缺失类别按零分母为 0 的规则计入 macro；与具体比赛的官方指标**未必一致**，口径不一致时不应强套本实现。
- 优化参考程序和原程序如果采用**同一个错误的目标公式或约束集合**，仍可能同时给出一致答案，所以要先回到原题核对数学模型，再用第二路线验算。
- 基准、敏感性、统计置信区间、因果识别、最优性的严格数学证明仍有其独立需求。

## 与论文写作如何衔接

正文中应先给原题答案，再解释方法和假设，再展示**独立复算/反例/失败样本**等能证明求解可靠的证据，最后给出有限范围内的结论。优秀论文只用于学习这一叙事结构，不应因为往届论文用过某算法就推断本届算法正确。保留所有不一致的复核日志与修复记录，和 `paper_evidence_gate.py --require-metric-source`、`result_invariant_gate.py` 联合使用。
