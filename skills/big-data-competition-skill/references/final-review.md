# Final Review

终审从评委视角检查四层：

1. 题目层：是否完整回答赛题。
2. 方法层：方法是否与任务和数据结构匹配。
3. 证据层：结果是否经过合理验证，是否存在泄漏或过度解释。
4. 论文层：图表、数字、引用、术语和结论是否一致。

高风险问题包括：无 baseline、随机切分时间数据、测试集调参、结果未复现、图表与正文数字不一致、因果过度声明、参考文献不可追溯。

最终结论必须标明 evidence boundary。
## v2.4 双轨终审，科学问题优先

**Scientific Reviewer** 先核查：是否回答官方目标；单位、边界、公式和代码是否一致；关键指标能否独立复算；预测是否泄漏；优化是否可行、是否真的最优；统计/因果识别是否成立；扰动实验是否证实所声称的稳定性；结论是否超过证据。任一关键失败均为 `blocking`，不得拿外观质量抵扣。

**Editorial Reviewer** 在上面完成后核查：全文主线是否由题目驱动、子问依赖是否清楚、方法选择理由是否接得上证据、图表是否回答问题、摘要与结论是否对应结果、讨论有无矛盾/冗余及引用是否真实。

参考 [通用正确性审核](solution-validity.md) 与 [论文逻辑审查](paper-argumentation.md)。两项都通过才考虑交付；“已填写 `passed`”不等于实际复核成功。

## v2.5 加强最终“结果确实回答原题”的反证门

论文质量与求解正确性需并行验收。完整跑过实验后，针对当届官方题意建立必要数值约束并使用 [通用结果反证工具](result-falsification.md)；关键论文指标在严格模式下强制回读 SHA-256 检验的真实源文件。**公式或约束错误、原始指标与正文不一致，均阻断终稿**；不能用“写作通顺”和“软件正常运行”抵消。

## v2.6 独立算式与实际指标复核

Scientific Reviewer 需检查 [参考复算与已知答案协议](independent-recomputation.md) 中的原始数据、模型契约、手工已知小例、不同实现以及负面案例。尤其核对分类宏平均口径、可行但次优的方案、状态空间上限和大问题的外推边界；单元测试通过不能替代实际验证与最终论文审阅。


## v2.7 未知赛题科学审稿的任务适配

对时序、统计推断、随机仿真或严格凸盒约束模型，在它们适用时采用 [扩展独立核对](extended-oracles.md)；审稿人还需攻击方法假设、原始验证数据可用性和强结论。若是其他任务，提出该题特有的手算、证明、守恒、独立求解器或不确定性检验，不能因为通用工具不支持就跳过验证。

## v2.8 项目级跨模块数值闭环

在独立科学审稿和编辑审稿之间，建议补做 [项目级证据链与失败关闭检查](project-evidence-chain.md)。此工具验证全部题目覆盖、SHA-256 引用、独立 oracle 的论文指标映射、输出不变式的原始数据关联及稳定性 anchor。任何一个关键环节失败即阻断项目机器验收。即使返回 `machine_evidence_consistent`，仍必须**人工**核对题意、来源数据、统计前提和完整论文逻辑。
