# 大数据挑战赛全流程 Skill

## 定位

本 Skill 专门服务于赛题未知、方法未知、最终需要提交论文的大数据挑战赛。

它不是固定的机器学习 Skill，也不是传统数学建模 Skill。面对新赛题，必须根据数据、任务目标、评价指标和约束动态选择统计学、计量分析、机器学习、深度学习、时间序列、空间分析、图网络、运筹优化、仿真或因果分析等方法。

核心原则：先理解问题与数据，再选择方法。先建立可信基线，再追求提升。所有论文结论必须能追溯到数据、实验或数学推导。

## 主工作流

赛题与附件审计 → 问题拆解与任务类型识别 → 数据资产盘点 → 数据质量审计 → EDA → 泄漏检查 → 明确评价指标与验证方案 → 候选方法比较 → Baseline → 特征与变量构造 → 主模型 → 对照实验与消融 → 稳健性验证 → 结果深化分析 → 图表 → 论文证据链 → 竞赛论文 → 终审与可复现交付。

任何阶段发现上游事实变化，都必须回退到受影响阶段，不得用下游文字或图表掩盖上游变化。

## 1. Problem Contract

开始时冻结：

- 赛题目标与每个子任务
- 输入数据、字段和数据字典
- 输出要求
- 官方评价指标
- 时间范围与预测时点
- 样本粒度与实体粒度
- 已知约束与业务规则
- 可用外部数据
- 禁止或不确定事项
- 子任务之间的数据和结果依赖

不能因为某种算法方便、已有代码存在或数据表长得像某种任务，就反推题目含义。

## 2. 数据审计

所有数据先审计，但不是所有数据都必须清洗。

检查文件、表、字段、类型、单位、粒度、缺失、重复、异常、时间覆盖、主键、实体重复、跨表连接、训练测试边界、标签定义、标签延迟、样本选择偏差和分布变化。

必须主动攻击 target leakage、temporal leakage、group leakage、duplicate contamination、join leakage 和 preprocessing leakage。

数据处理必须可解释、可复现、可回滚。不得静默删除数据、静默降采样或为了得到更好结果修改验证集。

## 3. 方法选择

先识别任务结构，再选择方法：

- 描述规律与推断：描述统计、假设检验、回归、置信区间
- 数值预测：回归、树模型、Boosting、时序模型、深度学习
- 分类：线性模型、树模型、Boosting、神经网络
- 无标签分组：聚类、降维、表示学习
- 时间依赖：滚动特征、状态空间、ARIMA 类方法、Boosting、序列模型
- 空间与网络：空间统计、空间权重、图算法、图模型
- 资源配置、路径、调度：线性规划、整数规划、动态规划、启发式或元启发式
- 随机过程与风险：蒙特卡洛、情景分析、随机模型
- 因果问题：明确识别策略和因果假设

不要默认深度学习优于传统模型，也不要为了模型高级而强行增加复杂度。

候选方法必须比较可解释性、数据需求、计算成本、任务匹配度、验证难度、稳健性和论文可解释性。

## 4. Baseline 与模型竞争

复杂模型前必须建立可信 Baseline。Baseline 可以是简单统计规则、历史均值、线性模型、简单树模型或官方基准。

每次模型升级必须回答：相比 Baseline 改善了什么？改善是否来自有效信息，而不是泄漏、数据处理差异或偶然划分？

最终论文不能只报告最好模型。至少保留关键 Baseline、候选模型和最终模型的可比较结果。

## 5. 验证

验证方案必须匹配真实任务：

- 随机任务：合理交叉验证或独立测试集
- 时间任务：时间切分、滚动验证或回测
- 分组任务：Group-aware split
- 空间任务：空间阻塞或区域外验证
- 极度不平衡：分层指标和与任务匹配的指标
- 排序推荐：与排序目标匹配的验证
- 仿真随机模型：重复实验和收敛诊断

出现异常高分时，优先检查验证设计，而不是直接接受结果。

## 6. 实验治理

每个关键实验至少记录：

experiment_id、data_version、feature_version、method、parameters、validation_scheme、random_seed、metrics、runtime、artifacts、decision。

结果必须能够回答：哪个模型产生、用了什么数据、哪个特征版本、什么验证方式、为什么选择、是否重复验证、有什么局限。

主结果与结果深化分析分离。不要为了绘图或论文修改主求解代码中的核心结果。

## 7. 消融、敏感性与稳健性

根据题型选择特征消融、模块消融、参数敏感性、样本扰动、时间窗口变化、空间区域变化、随机种子重复、Bootstrap、外部验证或极端场景测试。

每项实验都必须对应一个明确问题，而不是为了增加表格数量。

## 8. 图表

正式图必须来自真实计算结果，不允许为了视觉效果制造趋势。

图表优先回答：数据分布、变量关系、时间趋势、空间差异、模型对比、消融、敏感性、误差诊断、预测与真实值差异、特征重要性或模型解释。

每张正式图建立 图号 → 数据来源 → 计算脚本 → 结论 → 论文位置 的追踪关系。

论文图优先采用简洁、克制配色、统一字体和统一坐标规范，不用装饰性 AI 图片替代数据图。

## 9. 论文证据链

从建模阶段就建立：

赛题要求 → 数据证据 → 方法或数学关系 → 实验设计 → 数值结果 → 图表 → 论文结论。

每个关键结论必须由数据、实验、数学推导或可靠文献支持。

不能从相关性直接写因果，不能从单次实验写稳定提升，不能从一个数据集写普遍有效。

## 10. 竞赛论文

默认论文结构按赛题调整：

摘要；问题重述与任务分析；数据来源与预处理；各任务的模型与算法；实验与结果；模型比较；敏感性或稳健性分析；讨论；模型优缺点与适用边界；结论；参考文献；附录。

每个任务尽量闭合为：

任务目标 → 数据与变量 → 方法选择理由 → 模型或算法 → 参数与训练设置 → 实验设计 → 结果 → 解释 → 小结。

代码实现细节、文件路径、DataFrame 操作和日志内容不得直接塞进论文正文。

## 11. 可复现交付

正式结果绑定：

题目与数据版本 → 数据处理版本 → 代码版本 → 参数 → 随机种子 → 验证方案 → 结果文件 → 图表 → 论文。

如果用户本地执行题目代码，Skill 负责生成、静态检查、审查和解释代码，不伪造本地运行结果。

## 12. 终审

提交前检查：

- 是否真正回答全部子任务
- 数据处理是否有依据
- 是否存在泄漏
- 验证方案是否可信
- Baseline 是否充分
- 最终模型是否优于合理基线
- 关键结果是否可复现
- 图表与正文是否一致
- 数值是否前后一致
- 论文结论是否超过证据边界
- 参考文献是否真实可追溯
- 代码、数据、结果和论文是否版本一致

最终目标不是模型最复杂，而是：问题理解正确、数据可信、方法匹配、实验充分、结果可复现、论文证据闭合。

## 输出合同

需要形成阶段性决策时，优先输出：

Problem、Inputs、Checks performed、Findings、Decision、Risks、Next actions、Artifacts。

不要为了形式输出无意义的长报告。
