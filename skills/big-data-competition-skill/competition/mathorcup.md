# MathorCup 大数据竞赛画像

> 本文件是 MathorCup（高校数学建模挑战赛——大数据竞赛 / MathorCup 数学应用挑战赛——大数据竞赛）的竞赛画像。
> **历史规律只用于快速建立心智模型，不代表当届规则。** 页数、匿名、提交文件、AI 披露等一切当届要求，必须以当届题面与官方通知（赛氪/官网）为准，核验后再执行。

## 1. 赛制

- 分 **赛道 A、赛道 B**，两条赛道独立命题、独立评审。
- 每条赛道分 **初赛 → 复赛**：初赛通常 3 个问题，复赛通常 2 个问题（复赛在初赛基础上扩展、加深）。
- 最终成果 = **一篇竞赛论文 + result 结果文件**；部分赛次要求代码、非技术报告。
- 论文封面通常需写明 **队伍编号、赛道、论文题目**。

## 2. 赛道画像（2021–2025）

| 年份 | 赛道 A | 赛道 B |
|---|---|---|
| 2021 | 二手车估价（回归，MAPE/Accuracy5）+ 成交周期因素分析 | 信息流推荐序列收益评估（点击/时长，listwise + 剪枝） |
| 2022 | 家政订单分配（多目标加权，贪心/整数规划，批量派单） | 移动用户满意度（因素量化 + 评分预测） |
| 2023 | 坑洼道路 CV（图像二分类 → 边缘分割/面积） | 电商需求时序预测（冷启动/促销）+ (s,S) 库存补货 |
| 2024 | 台风分类与路径预测（聚类 + 路径/风速/雨量预测） | 电商货量预测 + 分仓多目标规划（MILP/NSGA/MOPSO） |
| 2025 | 集装箱 CV（分类 → 检测分割，多尺度/不平衡） | 物流理赔（无监督标注 + 回归 + 直接分类 + Stacking） |

**经验画像（仅参考）**：赛道 A 常围绕一种“当热模态”（CV 图像、时空轨迹）；赛道 B 常围绕企业表格/运营（预测 + 优化）。两赛道都可能出现“先建模、后比较方法论、再优化决策”的递进链。

## 3. 问题递进的常见模式

- **标注 → 预测 → 分类 → 方法论比较**（2025 B：无监督风险标注 → 赔付金额回归 → 风险直接分类 → 比较“回归+规则”与“直接分类”）。
- **预测 → 库存/分仓优化**（2023 B、2024 B：需求/货量预测 → (s,S) 补货或多目标分仓）。
- **分类 → 检测 → 分割**（CV：先判有无残损，再定位与识别类别，再分割/估计面积）。
- 最后一问常要求：方案优缺点总结、非技术报告（1–2 页）、或创新方案论证。

## 4. 数据特征

- 真实业务数据，常含：脱敏/匿名特征、高基数 ID（用户/网点/商品/城市）、缺失值、异常值、时间戳、跨多表关联。
- 视觉赛道：图像背景复杂、光照/阴影/污渍干扰、目标多尺度、类别/正负样本不平衡。
- 部分赛次提供“字段说明/数据描述”附件，**必须先读**，用于核对字段含义与单位。

## 5. 提交物与 result 文件规范

- result 文件使用官方模板（CSV / XLSX / TXT），**不得改文件名、列名、分隔符、编码，不得改变 ID 与样本的对应关系、不得增减样本行**。
- 常见分隔：CSV 逗号、部分 TXT 为 `\t`；编码以模板为准（提交前用二进制/编码检查确认，避免中文乱码）。
- 多结果文件常需打包为指定 zip 后提交。
- 逐项校验见 `../../templates/result_checklist.md`。

## 6. 论文格式（经验结构，以当届模板为准）

封面（队伍编号/赛道/题目）→ 摘要（分问题写方法 + 关键数值 + 结论）+ 关键词（3–6）→ 目录 →
一、问题重述（背景/目标任务）→ 二、模型假设及符号 → 三、问题分析（每问：核心剖析 + 解决思路 + 技术路线流程图）→
四、问题一模型建立与求解（EDA → 建模 → 求解 → 校验 → 小结）→ 五、问题二… → 六、问题三… →
七、模型评价与推广（优点/缺点/推广）→ 八、参考文献 → 九、附录。

具体篇幅、图表密度与获奖论文特点需根据实际已审阅 PDF 和当届规则核对，不得把未经证实的统计数字作为固定要求。正文只使用有分析价值的图表，附录依据当届要求。

## 7. 当届规则核验清单（必做）

- [ ] 当届赛道划分、每个问题的输入附件与输出字段；
- [ ] 预测类问题的官方评价指标与口径；
- [ ] 结果文件名、格式、分隔符、编码、sheet 名；
- [ ] 页数上限、匿名要求（队伍编号如何出现）、AI 使用披露；
- [ ] 是否要求代码、非技术报告、打包方式；
- [ ] 关键时间节点（验证集/测试集何时发布、截止时间）。

以上每条都要能指回当届题面或官方通知；核验不到的项标“待确认”，不得用历史默认值填充。

## 2025 赛题历史附件真实性（v2.3）

经实际核对 [supreme-spoon 的 2025 A/B 文件元数据](real_case_2025_profiles.json)：A 目录包含 train/test 图像 3300/413 及对应 bbox 标注，公开的 test 标签不能用于模型开发；B 的 XLSX 在连接器返回的是 LFS 指针，附件1 报告大小仅 2 字节。应先取得原始真实附件，按 [就绪检查协议](../references/real-case-replay.md) 运行预检，再开展正式模型。
