## B. 推荐序列评估（2021 B）

### 1. 问题本质

对“候选推荐序列”评估**整体收益**：总点击量 + 总浏览时长；需考虑内容**排列组合**（listwise）而非仅单内容打分（pointwise）。

### 2. 建模思路

```python
# 特征：用户历史（点击/时长/时间）、内容属性（类型/类别）、序列上下文、位置
# 单内容：预测点击概率 p_click 与期望时长 E[t]
# 序列层：建模位置效应与内容间相互影响（相似内容集中会降低收益）
# 序列收益 = Σ 位置加权的点击/时长 + 排列组合项
```

### 3. 生成最优序列（复赛）

```python
# 目标 argmax Q(u,r)，内容库百万级、单用户限时（如 800ms），不能暴力枚举
# 先用 pointwise 打分召回 Top-N（剪枝），再在小集合上做序列级优化
# 贪心/束搜索(beam search)生成排列，排除已推荐过的内容
```

### 4. 剪枝策略（题目明确要求）

- 用低复杂度召回（内容打分 + 类别去重/多样性约束）把候选从百万剪到少量；
- 报告**剪枝精准度**（最优序列被保留的概率，可用小集合离线评估）与**时间复杂度**。

## C. 验证要点

- 文本：人工抽查分词/主题合理性，分类用 F1；不臆造文本含义。
- 推荐：时间/用户切分防泄漏，报告点击与时长各自误差；离线评估与线上口径一致。
- 生成序列满足约束（长度、去重、限时），报告运行环境与耗时。
