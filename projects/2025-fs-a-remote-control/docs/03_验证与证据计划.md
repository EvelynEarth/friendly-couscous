# 三、问题一验证与后续求解证据计划

## 3.1 建模独立验证

- 结构：核实实际流向顺序1至14；订单释放时间；MU订单归属、零件批量与Exit记录；检查外观检双件成批逻辑和尾端装箱。
- 资源：每个处理节点同时在加工数<=已配置工作单元数；WorkerPool/设备共享数量不超限，班次休息动作可从事件日志证实。
- 质量守恒：任意时刻已产生MU=已完成MU+在制MU+合法报废/移除MU，禁止负WIP与幽灵工件。
- 时间：`release<=start<=finish`；无故障无返工时工序加工累计与配置一致；输送路段物理速度和路径长度校验。
- 实验时窗：在6000s前未完成的订单不能标注准时或延期完成；单独输出`unfinished_count_at_6000`。
- 标称产能审计：题面的1028件/小时只当作待验证引用值，不应预先设置成正确的仿真结果；单线能力与八线合计能力分别核算。

## 3.3 子问题路线及审批门

- Q1：单线原型事件级核验→8线全系统资源与布局→完整A基线→记录并验收结果。不可跳过8线。
- Q2：优先选择**C：测试资源微调**，因为场景C直接围绕电性能/单键测试并可建立对照；是否加入场景B（O11）作为扩展，待基线资源能力核实后决策。
- Q3：先用Gantt/WIP/排队与利用率查明真实瓶颈；DOE调整可控资源及缓冲参数；需要时针对大规模离散搜索再选择GA，而非先预设GA。
- 有随机扰动的场景必须同种子/共同随机数配对或多种子重复，报告平均、离散度及置信区间；不以单次运行宣称稳健。
