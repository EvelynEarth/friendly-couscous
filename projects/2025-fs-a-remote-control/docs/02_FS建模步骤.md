# 二、FactorySimulation 问题一操作路线（2022手册依据）

> 这是可执行建模步骤规划，不是已经在FS里完成的操作；所述菜单/对象需核实本机版本。
> 手册正文主要对应3.1基本对象63—96页、3.2物流设施97—131页、2.6界面及控制11—61页、4脚本191—217页。

## 2.1 最小可运行验证模型（单线原型）

1. 新建FS模型，设置模型名称/描述，保存`.fs`；确认仿真时间单位和物理尺寸比例。建议命名`2025A_single_line_prototype.fs`（尚未创建）。
2. 从“基本对象”工具条创建Entrance、Exit、14个处理节点，按题目图2顺序以Connector连接；如需真实输送，使用ConveyorLine站点并在必要处接入、接出工位。不要同时以Connector速度和输送线重复计算同一段移动时间。
3. 每个处理节点的基础参数来自`data/operations.csv`：加工时长（先取定值）、操作名称、工人数量列作为**需求待核验信息**，不要当作并行工位数。建议统一编号`S01..S14`。
4. Device内部无缓冲且一次只处理1个MU；WorkStation带缓冲并支持并行工作单元。选哪一类取决于核实的工序能力；先按一个单件工作单元验证顺序（工序10外观检需单独处理两件/批逻辑），不能据此宣称重现标称产能。
5. 在工序前按需要放置Buffer`B01..B14`，容量暂15（试验参数），明确已含WorkStation自带Buffer时是否额外加队列；由Buffer执行固定FIFO基线。原手册相关调度包括FIFS、SPT、EDD、SEQUENCE等。
6. 配置Entrance的订单产生方式（手册3.1.1）：可用订单Table或自定义Method；必须保留订单号、型号、释放时刻、交期、优先级等MU属性。先用O1—O10原始10单生成241件；原题表3到达时刻为绝对时刻，订单批量与产生次数字段不能混淆。
7. 在一条逻辑线原型检查：14道顺序、无遗漏/重复处理、每件在时窗中有唯一状态、最终Exit统计正确、订单完整性正确。
8. 工序10属于`2件/批 × 15.3秒`语义：采用专用缓冲/批处理方法或自定义脚本，记录不足2件时的等待和批处理结束时同时释放。先验证两件小样例；切忌默认按15.3秒/单件处理后直接认可结果。

## 2.2 工人池与物理资源

- 手册对象：WorkerPool（工人池）、WorkPlace（工位）、FootPath（步行道），以及资源池ResourcePool/ResourcePlace。
- 题目要求多工位共享可呼叫工人，完工返回；实现需确认本机FS版本中WorkerPool的请求/归还API、多人协作处理和班次休息行为。2022手册目录有若干“资源”小节缺失，不要捏造按钮或Java方法名。
- 采用工厂日历设置0—3600工作、3600—3900休息、3900—6000工作，**必须指定到实际资源/设备**后验证生效（手册2.6.12.2）。
- 各工序人员数总和33；后续八线复制前确定此数字和3个间接人员的作用域及共享关系。

## 2.3 从原型扩展到8条线

- 采用ObjectGroup分层组织，每条生产线单独命名`L01..L08`；`.fsb`是可复用的自定义子模型，但需注意其依赖和软件许可。
- 扩展时增加订单分派Method，把订单产品与交期保持在MU自定义属性中；检验均衡分派、每线资源约束、跨线共享人员及搬运冲突。
- 图3展示8线布局；不要把一条逻辑线原型冒充“8线全厂”；真实布局核实比例后再叠加生产车间图像。
- 原题给出8台测试电脑、2台螺丝机、1台热风机，必须确定其作用域后配置，避免每条线复制一次而无意扩大可用设备数。

## 2.4 仿真运行与报告

- 仿真工具栏设置运行范围；建议先无随机性跑简化小样例，再正式跑0—6000s场景A；对未完订单保留在制与状态记录。
- 开启仿真过程记录：手册2.6.11.2说明设备利用率、甘特图、WIP、零件通过时间图依赖过程记录；只为提高运行速度关闭动画，不能无提示关闭记录。
- 采集Gantt、Utilization、WIP、CycleTime、Exit完成历史、订单级C_j与延期、Buffer队列，以及必要的对象属性与工人池截图。
- 不额外注入B—E的故障、返工、紧急插单作为A的基线；对比实验保持未改变因素一致。

## 2.5 不宜提前编造的软件实现

- **未生成**FS可执行模型`.fs`或其截图；未运行FS。
- 2022手册只证明上述功能类别和部分UI，不能保证你实际安装的版本有同名按钮。
- 未证明WorkerPool支持多人协作的逐个具体API、外观检批处理自动原语；这两项需要软件界面或实际调试结果才能锁定具体实现。
